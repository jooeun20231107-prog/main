# Event ON v2 — 행사 자동 설계 플랫폼

밝은 대시보드, 행사 입력, 자동 배치, 동일 좌표를 공유하는 2D/3D, 독립 방문객 시뮬레이션, 세 배치안 비교, 계정별 프로젝트 저장, PNG/PDF 보고서를 포함하는 Streamlit 앱입니다.

## 빠른 실행

Python 3.11 이상을 권장합니다.

```bash
pip install -r requirements.txt
streamlit run app.py
```

첫 화면에서 회원가입하고 로그인한 후 ‘행사 설계’에서 입력 → ‘자동 배치 생성 및 프로젝트 저장’을 누르세요. 시설 위치와 배치안을 적용하면 프로젝트도 저장됩니다. 설계 메뉴에서 JSON 백업, 프로젝트 메뉴에서 JSON 복원이 가능합니다.

## GitHub / Streamlit Community Cloud

이 ZIP의 파일을 저장소 최상위에 그대로 올리세요. 숨김 폴더 `.streamlit`도 함께 포함합니다. Cloud에서 저장소를 연결하고 Main file path를 `app.py`로 지정합니다. API 키는 필요 없습니다. `packages.txt`는 한국어 이미지용 폰트를 설치합니다. 3D는 외부 cdnjs의 Three.js와 WebGL을 사용하므로 인터넷/CDN 접속이 필요합니다.

**SQLite는 Cloud 영구 저장소가 아닙니다.** 같은 파일이 유지되는 로컬 실행에서는 재접속 후 설계를 복원하지만, Cloud 재배포·재시작 등으로 계정과 프로젝트가 유실될 수 있습니다. 실제 플랫폼 운영에는 관리형 외부 DB와 운영용 인증이 필요합니다. 반드시 JSON 백업을 보관하세요. DB·비밀번호·개인정보 파일을 GitHub에 업로드하지 마세요.

## 파일 구성

- `app.py`: 홈, 입력, 설계, 비교, 프로젝트, 보고서, 설정
- `eventon_space.py`: 배치, 수요 가중치, 경로, 지표, 공통 공간 데이터
- `geometry.py`: 외곽선, 충돌/간격 검사, 출력용 설계도
- `space_viewer.html`: 2D/3D 및 브라우저 군중 시뮬레이션
- `storage.py`: SQLite 계정/소유자별 프로젝트 저장
- `report.py`: 행사 개요·도면·좌표·지표·한계를 포함하는 PDF
- `requirements.txt`, `packages.txt`, `.streamlit/config.toml`: 실행 설정
- `TEST_RESULTS.md`: 검증 내용

## 설계 엔진

공간 단위는 m입니다. 2D XY를 3D (X, 높이, -Y)에 매핑하며 같은 polygon, 시설 좌표/크기, 출입구를 사용합니다. 시설은 경계, 다른 시설 및 예약된 주 통로와의 간격을 검사해 배치합니다. 배치할 수 없는 시설은 누락 경고와 개수 차이로 표시합니다. 원형·돔형·정사각형은 가로/세로 중 작은 값을 지름/한 변으로 사용합니다.

방문객 수는 시설 크기에 제한적으로 반영하고, 행사 유형·분위기·연령대·운영시간은 시설 선호 가중치에 반영합니다. 예산은 기록용 계획 금액으로 자동 견적을 산출하지 않습니다. 추가 요청은 기록하며 자연어를 자동 공간 제약으로 변환하지 않습니다. 각 시설 종류는 한 개의 대표 구역으로 배치하며, 부스 개별 수량·가변 치수 편집은 포함하지 않습니다.

동선 균형형, 응급 접근형, 혼잡 분산형은 서로 다른 목적함수 가중치를 사용합니다. 이름은 설계 의도이며 해당 지표가 항상 다른 후보보다 우수함을 보장하지 않습니다. 연결 시설 수와 거리 등 실제 계산값을 비교하세요. 무조건적인 ‘최적’, ‘안전 95점’ 같은 점수는 제공하지 않습니다.

## 방문객 시뮬레이션

- 일부 방문객은 행사장 내부에서, 일부는 입구 인근에서 서로 다른 지연 후 나타납니다.
- 시설 선호에 따른 목적지 선택, 개인별 공간 비용과 현재 혼잡 비용을 반영한 A* 경로를 사용합니다.
- 서로 다른 속도, 체류 시간, 시설별 목적, 여러 시설 이용 후 퇴장을 표현합니다.
- 근접 반발과 감속, 최소 거리 이동 거부, 정체 시 목적 슬롯 재선정/경로 재탐색을 사용합니다.
- 체류 슬롯은 부스 외부 자유 공간입니다. 의료 접근 경로에는 체류 슬롯을 두지 않습니다. 다른 사람의 통과까지 차단하는 전용 의료차로는 아닙니다.
- 체류 분포는 화면의 누적 에이전트 위치 빈도입니다. 현재 표시 인원·정체/대기·누적 시설 이용을 표시합니다.

**한계:** 완전한 개인 간 충돌 해결, 서비스 처리 용량 기반 대기열, 실제 이동 데이터로 보정된 군중 모델은 아닙니다. 초기 생성에서 가까운 사람이 생기거나 좁은 길에서 교착/정체가 지속될 수 있습니다. 모든 사람이 같은 지점에서 출발하지 않도록 분산하지만 여러 실제 출입문·출입문 폭을 모델링하지 않습니다. 표시 인원은 총 방문객 수와 독립적인 시각화 샘플이며, 총 인원이 증가한다고 동일 비율의 실제 밀도를 재현하지 않습니다. 브라우저 실행 중 시뮬레이션 상태·통계는 저장되지 않고 설계 데이터·가정·시드만 저장됩니다. 리셋/화면 재실행 시 시뮬레이션은 초기화됩니다. 완벽한 재현성은 브라우저 시간 간격에도 영향을 받습니다.

## 지표 해석

- 평균 접근 거리: 입구에서 각 시설 외부 접근점까지 최단경로의 가정 수요 가중 평균
- 의료 평균 거리: 연결된 다른 시설에서 의료센터 외부 접근점까지의 평균 경로 거리
- 주요 시설 이격: 공연장·푸드존·체험부스·굿즈 중심 간 평균 직선 거리
- 경로 중복 비율: 입구 최단경로 셀 중 수요 가중치 합이 0.6을 넘는 셀 비율
- 시설 점유율: 시설 면적 합 / 격자로 근사한 행사장 면적

의료 평균 거리·접근 거리에서 미연결 시설은 제외되므로 연결 수를 반드시 함께 보세요. 경로 중복 비율은 통로별 실제 혼잡 밀도·처리 용량이 아닙니다. 동적 이동 결과를 배치 엔진에 반복 피드백하는 학습 최적화는 구현하지 않았습니다.

## 보안과 운영

비밀번호는 개별 salt + PBKDF2-HMAC-SHA256(310,000회)로 저장하고 프로젝트 조회/수정에 소유자를 검사합니다. 로그인 시도 제한은 세션 단위의 데모 보호입니다. 운영 서비스에는 서버 측 제한, 이메일 검증, 비밀번호 복구, 모니터링, 백업, DB 마이그레이션, 보안 검토가 필요합니다.

## 디지털 트윈/AI 표현

현재 버전은 기하 제약과 휴리스틱 기반 자동 설계 및 가상 에이전트 시뮬레이터입니다. 학습된 예측 AI, 실시간 센서 연동 디지털 트윈, 대피 검증, 안전 인증이 아닙니다. 실측 도면·고정 장애물·문 위치·폭·시설 실측·관측 데이터와 별도의 안전 검토를 연결해야 운영용 트윈으로 발전시킬 수 있습니다.

## 배포 후 확인

1. 회원가입/로그인 → 기본 행사 생성
2. 2D/3D 전환, 회전/확대, 시설 클릭 경로 확인
3. 시설 이동 후 두 화면 위치 일치 확인
4. 시뮬레이션 정지/리셋/인원 변경/체류 분포 확인
5. 후보 비교/선택 → 프로젝트 다시 열기 → 좌표 유지 확인
6. JSON 백업·복원, PNG와 PDF 한국어 출력 확인

실제 Streamlit 웹 세션과 WebGL 화면은 이 제작 환경에서 실행하지 못했습니다. Python·경로/저장 로직과 JavaScript 시뮬레이션 계산 검사는 수행했습니다. 상세 범위는 TEST_RESULTS.md를 참고하세요.
